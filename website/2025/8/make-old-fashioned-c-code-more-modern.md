# 让早期 C 代码更加现代化

## 引入

这是在慕课上看到的一个 C 语言的 ppt，主题是「符号常量」，小标题是「在程序中指定用一个标识符代表一个常量」，ppt 上的代码如下：

```c
【例】输入一个半径值，求圆周长和圆面积
#include <stdio.h>
#define PI 3.14159
void main()
{
    double r,k,s;
    scanf("%lf",&r);
    k=2*PI*r;
    s=PI*r*r;
    printf("circle：%.2f  area：%.2f\n",k,s);
    //其中%.2f表示保留两位小数
}
```

这段代码复现了 ppt 中的**原始版本**，包括格式和注释。

作为一个教学案例，这段代码是及格的，我可以给它评个 65 分或 70 分。

为什么？因为这段代码是可运行的、正确的。

在 Linux 上测试，gcc 15.2.1、clang 20.1.8 均可编译，且结果符合预期。

## 正确性（Correctness）

正确性意味着程序可以编译，即在语法上是有效的 C 代码。

正确性也意味着代码能够正常工作，运行结果符合预期。

在评价代码质量中，正确性往往是最重要的一个指标——毕竟，程序的首要目标就是正确实现功能。

## 设计（Design）

但一个好的程序不应该只是做到了正确，就以此代码为例，它是正确的，但绝对不算一个「设计良好」的代码。

如果你在编译时启用了 `-Wall` 标志（即启用警告），clang 和 gcc 都会指出 `void main()` 的问题。

```text
warning: return type of 'main' is not 'int'
```

在 1980 年代早期，C 语言的许多编译器支持 `void main()`，该写法广泛流传，并成为事实上的标准。

但在 1990 年代初期，**C89/C90** 以及 **C++98** 标准明确要求应使用 `int main()`，但许多编译器仍兼容 `void main()` 的写法，因此该写法在教材和代码示例中得以流传。

但在现在，在这个示例中，这并不是一个好的设计。

除此之外，这段代码仍有一些设计上不那么好的地方。

```c
double r,k,s;
```

例如，在 main 函数的第一行声明所有需要的变量。

这也是一个历史遗留的设计（早期的语言限制）：在 **C89** 以前，变量必须在代码块开头集中声明。

**C89** 放宽了这一限制，而 **C99** 彻底取消了这一限制——现在你可以在任何需要的地方声明变量。

至此之后，写代码的最佳实践变成了这样：在你需要这个变量的时候，你才声明它，让变量的声明和使用尽可能靠近。

因此，上文的代码可以改为：

```c
double r;
scanf("%lf",&r);
double k=2*PI*r;
double s=PI*r*r;
```

当你需要它时，你再声明它。

除此之外，这段代码还有其他一些设计上的小问题，不过这些问题都偏主观，因此仁者见仁智者见智。

比如：

- 在获取输入前先输出一些提示（如 `"Radius: "`）
- 在 printf 中使用英文冒号而不是中文冒号

## 风格（Style）

与设计相比，风格更具有主观性，但仍有一些通用规则。

### 常量命名

- 推荐使用**全大写**字母和下划线组合（如 MAX_VALUE）
- 而非缩写（如 MAXVAL）

### 变量及函数命名

- 优先使用**语义化**（具有明确语义）名称来命名变量（如 radius）和函数（如 calculate_area）
- 尽量不要缩写，如 user_count 不要缩写成 ucnt
- 例外：循环计数变量允许 i、j、k

当然，这可能也算一个历史遗留问题——早期的 C 语言严格限制了标识符的长度，因此出现了各种缩写、简写。

但在今天，用语义化的名字是更推荐的。

### 格式化规范

一些格式化工具会帮助格式化，让你的代码看起来更整齐。

比如说，在所有的逗号后面加一个空格，例如 `double r, k, s;`

格式的美观与否取决于个人喜好，但保持一致非常重要。

请保持历史代码​​、​​团队约定​​、​​自身习惯​​的一致性。

## 总结

当阅读他人的代码或你以前写的代码时：

- 规范的命名可以快速定位变量，辅助理解
- 就近声明可以减小无关变量的干扰
- 良好的排版可以代码看起来更整齐、更美观

这就是为什么设计、风格、规范，都是代码质量的一部分。

初学者应养成良好的编程习惯，不要为了输入的方便写出过于简单的变量名，也不要为了压缩代码长度而使用糟糕的排版。

高质量的代码首先要正确，其次要做到符合规范、保持可读性，最终目标是实现可维护性——这建立在前三者之上。

## 附录

在此提供一份个人认为还算可以的代码：

```c
#include <stdio.h>
#define PI 3.14159
int main() {
    printf("Radius:        ");
    double radius;
    scanf("%lf", &radius);

    double circumference = 2 * PI * radius;
    double area = PI * radius * radius;
    
    // %.2f 表示保留两位小数
    printf("Circumference: %.2f\n", circumference);
    printf("Area:          %.2f\n", area);
}
```

|分类|原始实现|优化后实现|理由|
|:-:|:-:|:-:|:-:|
|**改进**||||
|变量命名|`k`, `s`|`circumference`, `area`|语义化命名，提高可读性|
|变量声明|集中在函数开头|使用时声明（如`double radius`）|符合C99标准，减少变量污染|
|标点符号|中文冒号`：`|英文冒号`": "`（带空格）|符合代码国际惯例|
|代码排版|紧凑无缩进|合理缩进+操作符空格|提升视觉层次感|
|注释位置|printf 后（已使用 `%.2f`）|printf 前（未使用 `%.2f`）|符合教学直觉|
|**改动**||||
|变量命名|短名称（如`k`）|超长名称`circumference`|强调可读性优先|
|代码排版|集中|用空行分割|提升阅读体验|
|输出对齐|无特殊处理|使用空格占位（`"Radius:        "`）|实现列对齐的专业输出|
|输入提示|无|输出`"Radius: "`|改善用户交互体验|
|注释格式|`//%.2f表示...`|`// %.2f 表示...`|符合写作、注释惯例|

以下是该程序的一份输出：

```text
Radius:        114
Circumference: 716.28
Area:          40828.10
```
